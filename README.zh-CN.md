# 开放性数学研究

[English](README.md) · 简体中文 · [日本語](README.ja.md)

一套用于开放性数学研究的实验性 agent skill：保留原始问题，重新检查自加限制，减少过早放弃、目标偏移与代理交接中的目的损失。

它由内部试用中积累的研究建议和具体案例组成，尚未经过有效性对照评估。

## 它能提供什么

- 区分用户目标与模型自行选择的表示、中间引理和交付形式。
- 检查失败究竟来自哪个条件，将失败构造接到具体的下一项数学动作。
- 在追加昂贵计算、辅助工程或已偏离问题的证明之前，先使用简单对照。
- 在获准的分工与交接中保留原用途、公式、已成立事实和失败范围。

它适用于实际开放问题的探索，以及会影响后续研究决定的复盘和审查。普通习题、纯会话整理、不涉及研究判断的文献汇总通常不需要这套 skill。

## 使用方法

使用社区 skills CLI 从 GitHub 安装：

```sh
npx skills add isshiki-works/exploratory-math-research
```

也可以将完整的 `exploratory-math-research` 文件夹放入所用 agent 能识别的 skills 目录，保持 `SKILL.md` 位于文件夹根部。支持按名称调用 skill 的环境中，可使用：

```text
使用 $exploratory-math-research 研究以下问题：
[问题原文、允许的假设、已有工作和资源限制]
```

如果只需要复盘，请明确要求复盘，而不是恢复研究。skill 本身不授权增加代理、对外操作或扩大预算。

默认入口是[中文原文](SKILL.zh-CN.md)，另有包含全部执行方法和 18 个核心案例的[英文版](SKILL.en.md)与[日文版](SKILL.ja.md)。若希望使用其他语言作为入口，在**安装副本**中用相应文件覆盖 `SKILL.md`，保留其余文件。可选界面元数据分别位于 `agents/openai.en.yaml`、`agents/openai.ja.yaml`，需要时用对应文件覆盖 `agents/openai.yaml`。替换既有安装前保留备份。

较长的[历史研究笔记](references/discovery/index.md)目前为中文，是核心案例的补充，尚未全量翻译。阅读 skill 无需运行时依赖；实际研究使用什么工具，由具体任务决定。

## 作者声明

一色（Isshiki）

作为一位科幻作家，这套 skill 来自反复的内部开放问题研究，包括对雅可比问题相关工作的受限复现。在这些运行中，我观察到一系列模型过早放弃、目标偏移和设计代理交接损失的固定模式，并与astra一起尝试缓解。我把它作为一个初步方案公开，其中包含具体、细致的数学工作建议，从部分历史案例中进行提取，更适用于真正的开放问题。

它仍有赖于更准确的初始方向选择，以及正确的押注，这意味着机构级研究的优势不可能通过这类prompt追平，无论它是否低效，甚至更细致的启发性要求仍然无法逐步彻底抓住一切可能的路径，只是尽可能减少了一些显著不合理的投入和错误——但无法排除也许它是正确的。在此基础上，我希望它能改善现有可访问模型在有关路线的选择能力，减少过早放弃，也减少为了交付一份回答而过度投入无关证明。

没能完整进行有区分力的 A/B 测试。像评估 Ponytail 那样衡量这套 skill 究竟带来多少改善，需要消耗大量 token。目前没有能力和计划，为完整验证腾出足够的计算资源。它是在多个内部开放式数学问题挑战中蒸馏经验、吸取教训形成的；我们并没有使用它解决原本希望攻克的问题，但一个小范围进行的、通过雅可比的复现指出的成功模式与失败模式的经验已经初步支持了这类问题的存在。

2026 年 9 月 8 日，OpenAI 宣布给出 Navier–Stokes 存在性与光滑性问题的解答，并公开论文与 Lean 形式化证明，这几乎是整个skill以及个人相关工作的预言的最显著兑现。作为一位早期 AI 使用者，科幻作者，我对这样的发展感到焦虑，尤其担忧前沿知识的控制权以前所未有的程度集中于少数大型 AI 企业。

我希望这些工作能帮助所有愿意使用、质疑并共同建设这套 skill 的人。它的许多内容来自人类的数学智慧和长期积累。在这个时代改变的当下，我希望人们能够团结起来，尽可能共享已有的结果和经验，减少无益的浪费与封闭，共同面对一个全新的事实——新时代不在将来，而是从当下开始。

## 证据与时间

公开数学案例提供方法和启发，不是本项目取得的数学发现；案例正确也不等于 skill 有效。内部复现带有提示并共享部分上下文，不属于严格独立的无提示测试。跨模型、跨语言的行为等效性也尚未测量。
